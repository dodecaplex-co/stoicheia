- **CI in proportion to risk, part one: the landing tool's tests where a change reaches
  them, and the merge group's lane behind a switch (CI,
  [#888](https://github.com/dodecaplex-co/stoicheia/issues/888)).** On 12 November
  2026 the owner wrote, of CI: "yes 1 and 2. This is a bottleneck to fix. Risk is
  inappropriate Scope is inappropriate Runs too long on low risk changes, too short on high
  risk ones." (01:05), then "And ideally these linters / checks / scoped etc. run in
  preflight and Ci/CD checks them for speed. So that we don't wait 20 minutes on slow
  machines." (01:21:47), and "And again - tests should be scoped to relevance. With
  contracts and checks in code." (01:22:22). The same night he moved main's run after each
  merge, and the landing tool's whole suite at each merge that reaches it and once a day,
  to a machine of the project's own; CI's lane messages name that decision ruling 1581.
  Before this change no pull request ran `scripts/test_safe_push.py`, the tests of the
  gate every pull request lands through, but for one unit test; and a merge group that
  changed it ran the whole suite in one job, about 400 runner-minutes against a limit of
  150, which could not pass.

  `scripts/risk.py` gains the landing tool's inputs, `gate_inputs`: the paths of its R5
  rule; every file `scripts/safe_push.py` and `scripts/test_safe_push.py` import, directly
  or through one another, each import read by `ast` and resolved in the importing file's
  own folder and in each folder its own `sys.path.insert` names; the three data files
  beside the tests; and `GATE_EXECUTED`, the files the tests or the tool run or read
  otherwise, each with its citing lines. A change reaches them when a path of its diff is
  among them at either end. It fails closed: while a file the scan reads does not parse,
  or names a folder for `sys.path` the reader cannot resolve, every change reaches them.
  `--diff --github-output` writes `gate=true` or `gate=false` beside the class.
  `tests/test_risk.py` holds every `HERE /` and `SOURCE /` read of the two files, and each
  program they run by subprocess, to those inputs, and fails on a read it cannot resolve.

  `scripts/risk.py` also gains `GATE_READ_EXCLUDED`, the reads that are fixture data alone,
  and its switch `GATE_READ_EXCLUDED_LIVE`, False as built, so that every row still reaches
  the gate. Its one row is `assets/*.png`, which `tests/test_risk.py` shows no code under
  test opening, by an audit hook over `scripts/check_fidelity.py` and `scripts/render.py`
  as the tool runs them. `AGENTS.md` is no row: that trace shows both opening it, through
  `generated_counts.py`, which reads every tracked Markdown file. A row is added only by its
  own protected pull request, which names it in `tests/test_risk.py`'s `EXCLUDED_AS_BUILT`
  with an entry citing that test; the switch is set only by its own, whose grounds record
  runs of the whole suite on main, six hours apart at most.

  `.github/workflows/ci.yml` gains `gate-shards`, the suite in 12 shards on a pull request
  whose gate is not false, a gate main's `risk.py` does not give among them, and
  `gate-tests`, a required check of its own, which passes at once where the change reaches
  none of the inputs and is otherwise judged by main's `scripts/check_queue.py --gate-prove`,
  taken from the checkout's first parent. `scripts/safe_push.py` adds `gate-tests` to
  `REQUIRED_CHECKS`; adding it to main's ruleset is the owner's setting.

  `.github/workflows/queue-judge.yml` gains the queue's judge of the same tests, from
  main's copy: `queue-gate-plan` decides once whether the group reaches them,
  `queue-gate-shards` runs the group's own suite in 12 shards with no token, and
  `queue-gate` proves from the shards' lists that each test ran once and passed. In
  `scripts/check_queue.py`, `gate_reached` is that decision for both `--gaps` and
  `--gate-plan`: the tests queue-gaps chooses for the group's entries, each against its own
  merge base, or main's `risk.py` gate for the group's diff. `--gaps` now marks the suite
  carried by queue-gate and never runs it whole; `--gate-shard` runs one shard;
  `--gate-prove` admits only `ok` and the three skips `ALLOWED_SKIPS` names, each where its
  condition holds and with its exact reason. The shards' lists record each skip's reason and
  the shard's environment, and `--cover DIR --shards 12` takes its count from the plan.

  A merge group stays R5 while `GROUP_LANE` in `scripts/risk.py` is None, as built: the
  risk job's merge group case checks the group's ids, checkout, ancestry and pull requests'
  `release` labels, then asks main's `risk.py --group-lane`, and classes a group by its diff
  only once a protected pull request of its own has turned the lane on, for L6 (main's run
  after each merge, with an automatic revert of a red one shown working) or GROUP-VERIFY (a
  signed group checklist verified for every class). `tests/test_group_lane.py`, the check
  of `checks/33-group-lane.toml`, refuses either unless it is held in code; it runs beside
  the other concurrent checks, and `tests/test_concurrent_checks.py` adds it to the list of
  them its audit names (#608). Main's `risk.py` answer is now held to its form for a pull
  request and a group alike.

  Every job a required check names now takes one form, since GitHub counts a required job
  it skips as passed: no job-level `if` but `always()`, a first step that reads each need
  it decides on, and a last step under `always()` that judges its work step's outcome.
  `scripts/test_safe_push.py` holds that form in checks/24's lane-condition test, holds each
  workflow's new steps to their contracts, and holds the risk job's merge group case and
  gate-tests' steps case by case.

  `scripts/negative_tests.py` gives each worker its share in a run order of its own:
  plants the record does not name first, then those that build, longest first, then the
  rest; a run of one worker, and the run's printed output, keep the stable order.
  `tests/negative_times.json` is rewritten from the log of the merge group run
  43213322004's `negative` job, 54 of 54 plants, on GitHub's four-core runner.
  `tests/test_negative_tests.py` and `tests/test_check_queue.py` hold those changes.
  `docs/WORKFLOW.md`'s sections 8 and 10 say where each class's checks run. The group's own
  merge needs one admission past the queue's judge, which the owner approved in advance
  for this change alone, since main's old queue-gaps would run the whole suite in one job.
