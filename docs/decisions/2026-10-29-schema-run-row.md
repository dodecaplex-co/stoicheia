- **SCHEMA's `run` row names the forms the records use (records,
  [#264](https://github.com/dodecaplex-co/stoicheia/issues/264)).** The coordinator's
  orders of 29 October 2026, 20:20, assign card #264, which records the coordinator's
  ruling of 21 October in these words: "a run line names the brief and stage only when the
  work was done under one; card work names the card." This entry claims no approval of
  the owner's.

  `review/SCHEMA.md` described a record's `run` as "the brief and stage, and the workflow,
  as `"brief 0005 stage 5, workflow wf_…"`". On main at 684218630, 35 of the 99 run lines
  begin with a brief and stage; the rest begin with a card, a ship's orders, or who wrote
  the proof followed by a read-through; and 4 name a workflow. The row now says what a run
  line holds: the run the review was made in and each later reading, after a semicolon,
  each naming the work it was made for, with an example of each form taken from a record
  on main. It says too that `heath.load_review` requires a string that is not blank, and
  reads nothing of its form.

  `docs/WORKFLOW.md`, section 6, said the same of `run` in one clause, which now names
  both forms and points to the schema.

  One row of the schema and one clause of WORKFLOW change, and no record: no rule of the
  schema changes, and none is loosened, since no check reads a run line's form. This
  entry approves the change to `review/SCHEMA.md`, a protected path, in its `run` row
  alone.
