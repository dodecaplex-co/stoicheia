- **The review records' schema reads a `page` stamp, in form alone, before the stamp
  lands (checks, [#621](https://github.com/jackChallis/stoicheia/issues/621)).** Card
  #621 binds each review record to its page's commentary and figures with a fifth stamp,
  `page` in its `[review]` table, which a later train writes into every record and
  `check_fidelity.py` then requires. The pre-flight runs origin/main's checks on a train
  beside the train's own, and origin/main's `heath.load_review` refuses a key it does not
  know; so a train whose records carry `page` could not pass origin/main's checks until
  main reads the key.

  `scripts/heath.py` therefore reads `page` as an optional key of `[review]`, and refuses
  one that is not 64 lowercase hex digits. Nothing
  requires it, nothing computes it, and no record carries it yet: no check that holds now
  is changed, and a record without `page` reads as before. `review/SCHEMA.md` names the key
  as reserved for that stamp. The train that writes the stamp makes it required, and
  says so in its own entry; this one lands first, as the precedent of the `text` stamp
  did, whose key was read before it was required.

  `scripts/negative/malformed_page.py` is a new plant: I.1's record given a `page` that is
  not of that form must be refused by `check_fidelity.py`, naming the key.
